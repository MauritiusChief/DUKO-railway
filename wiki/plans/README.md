# 实施计划

本目录只保存需要多人协调或分阶段实施+审阅的方案。计划描述意图，不是当前架构事实。

## 路径

```text
wiki/plans/YYYY-MM-DD/<topic>.md
```

- 日期使用计划首次创建日期。
- `topic` 使用小写 kebab-case。
- 同一天可创建多份不同主题的计划。
- 待办、缺陷和需求进入 GitHub Issues，不在计划中维护长期任务池。

## 内容

计划至少包含：

- 状态、目标和非目标。
- 已由代码、测试或配置核验的现状。
- 方案与关键取舍。
- 数据、认证、外部系统和迁移风险。
- 自动验证、手动验证、发布与回滚方式。
- 关联 GitHub Issue。

实施完成后更新状态和实际偏差，并把稳定结论同步到对应 Wiki 或 `.agent/context/`。不得通过复制旧计划恢复已经失效的架构描述。
